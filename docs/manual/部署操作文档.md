# knowledge_shelf_query 部署与更新操作文档

## 一、文件说明

| 文件 | 用途 | 更新频率 |
| --- | --- | --- |
| `knowledge_shelf_query_runtime:v1.1.0` | Python 3.12、Docker CLI 和 Compose 运行环境 | 仅环境变化时更新 |
| `knowledge_shelf_query_<版本>.bin` | 应用代码、页面和静态资源 | 每次源码变化时更新 |
| `config/` | 下单、仪表板、测试单等运行配置 | 设备本地保存 |
| `robot_keyboard.env` | 机器人键盘配置 | 按现场需要更新 |

飞书规则源文件为 `ksq/feishu/rules.json`。打包后对应部署目录中的 `config/feishu_rules.json`，容器内路径为 `/app/feishu_rules.json`。现场修改规则文件后执行 `bash start.sh restart`，规则会在服务启动时重新加载和校验。

`.bin` 是由 ZIP 格式封装的单文件 Python 应用包，可在相同 Python 运行时中跨 x86 和 ARM 使用。它不是原生机器码，也不用于源码加密。

## 二、首次准备运行时镜像

运行时镜像基于 `python:3.12.13-slim-bookworm`，内置 Docker CLI `27.5.1` 和 Docker Compose `v2.33.0`，不包含项目源码、编译工具和第三方 Python 包。当前 ARM64 构建在本机显示约 `359 MB`，原运行镜像约 `2.17 GB`。

目标设备需要安装 Docker Engine，并提供 `docker compose` 或 `docker-compose` 命令供启动脚本使用。容器通过 `/var/run/docker.sock` 调用宿主 Docker；Docker CLI 和 Compose 已包含在镜像中，不需要挂载宿主机二进制文件。

只有基础镜像、Python、Docker CLI、Compose 或其他系统依赖发生变化时才需要重新构建运行时镜像。

在开发机执行：

```bash
bash devOps/build_push_aarch64.sh v1.1.0
```

生成并推送：

```text
hub.noematrix.cn/pharmacy/knowledge_shelf_query_runtime:v1.1.0
```

目标设备首次启动时会自动拉取该镜像；后续更新应用包不会再次拉取。

网络不稳定时，可在开发机将 ARM64 运行镜像导出并只传输一次：

```bash
docker save hub.noematrix.cn/pharmacy/knowledge_shelf_query_runtime:v1.1.0 \
  | gzip -1 > knowledge_shelf_query_runtime_v1.1.0_arm64.tar.gz

scp knowledge_shelf_query_runtime_v1.1.0_arm64.tar.gz nvidia@<设备IP>:~/
```

在目标设备导入：

```bash
gzip -dc knowledge_shelf_query_runtime_v1.1.0_arm64.tar.gz | docker load
```

导入后的镜像标签与 `docker-compose.yml` 一致，执行 `bash start.sh start` 时不会再拉取。

## 三、首次部署

### 3.1 开发机打包

```bash
bash deploy/make_package.sh v1.2.5
```

生成两个文件：

```text
deploy/dist/ksq_deploy_v1.2.5.tar.gz
deploy/dist/knowledge_shelf_query_v1.2.5.bin
```

部署包目录结构：

```text
ksq_deploy_v1.2.5/
├── bin/
│   └── knowledge_shelf_query.bin
├── config/
│   ├── dashboard_settings.json
│   ├── dashboard_active_order.json
│   ├── test_order_state.json
│   ├── order_config.json
│   ├── order_config.prod.json
│   └── feishu_rules.json
├── docker-compose.yml
├── robot_keyboard.env
└── start.sh
```

### 3.2 上传到目标设备

```bash
scp deploy/dist/ksq_deploy_v1.2.5.tar.gz nvidia@<设备IP>:~/
```

### 3.3 目标设备启动

```bash
tar xzf ksq_deploy_v1.2.5.tar.gz
cd ksq_deploy_v1.2.5
./start.sh
```

启动时会检查应用包、业务数据目录和运行时镜像。本地没有运行时镜像时才会拉取；如果存在同名旧容器，会先停止并移除旧容器，再启动当前部署包，否则直接启动。

启动后访问：

```text
http://<设备IP>:8765
```

### 3.4 非默认数据目录

默认目录：

| 数据 | 默认设备路径 |
| --- | --- |
| `config_pnp` | `/home/nvidia/compiled/PNPApp_deploy/config_pnp` |
| `KNOWLEDGE_DIR`（Knowledge 根） | `/home/nvidia/compiled/VfmApp_deploy/model/templates` |
| 默认实际目录 | `/home/nvidia/compiled/VfmApp_deploy/model/templates/knowledge` |

路径不同时执行：

```bash
CONFIG_PNP_DIR=/实际/config_pnp \
KNOWLEDGE_DIR=/实际/model/templates \
bash start.sh start
```

`KNOWLEDGE_DIR` 指向包含多个场景目录的 `model/templates` 根目录。启动脚本将它挂载到容器 `/data/knowledge`；默认「一键加载」读取 `/data/knowledge/knowledge`，页面也可以填写根下任意相对目录（例如 `pnp_percept/templates_260827` 或其 `.../knowledge` 子目录），不读取 VfmApp `config.yaml`。填写场景目录时会自动定位其 `knowledge` 子目录。根目录不存在时启动会终止；默认子目录不存在时仅提示警告，仍可在页面选择其他目录。

旧部署目录若仍把 `KNOWLEDGE_DIR` 配置为 `.../model/templates/knowledge`，启动脚本会自动提升到 `templates` 根目录并提示；其他自定义路径请改为新的根目录写法。

只切换同一根目录下的场景目录时，无需改挂载或重启，在页面填写新相对路径后点击「加载数据」；更换 `KNOWLEDGE_DIR` 根目录才执行 `bash start.sh restart`。默认目录的 JSON 内容更新后，页面点击「一键加载」即可。

## 四、日常源码更新

源码、HTML、CSS 或 JavaScript 变化时，只更新 `.bin`，无需构建或拉取镜像。

版本若同时修改了 `start.sh` 或 `docker-compose.yml`（例如 Knowledge 挂载方式变化），必须更新完整部署包或手工同步这两个文件；`start.sh update <应用包.bin>` 只替换应用包，不会更新部署配置。

### 4.1 开发机构建应用包

```bash
python3 deploy/build_app_bin.py v1.2.6
```

输出：

```text
deploy/dist/knowledge_shelf_query_v1.2.6.bin
```

构建完成时会显示文件大小和 SHA256。

### 4.2 上传应用包

```bash
scp deploy/dist/knowledge_shelf_query_v1.2.6.bin \
  nvidia@<设备IP>:/tmp/
```

### 4.3 目标设备更新

在当前部署目录执行：

```bash
bash start.sh update /tmp/knowledge_shelf_query_v1.2.6.bin
```

更新过程会自动执行：

1. 校验新应用包的完整性和必需文件。
2. 将当前应用包备份为 `bin/knowledge_shelf_query.bin.bak`。
3. 原子替换应用包。
4. 重建容器，使新代码生效，并等待状态接口就绪。
5. 新版本未能正常启动时自动恢复上一版本；成功后显示当前版本。

该过程不会执行 `docker pull`。配置文件、测试单状态和当前工单状态不会被覆盖。

## 五、版本检查与回滚

查看当前应用版本：

```bash
bash start.sh version
```

查看服务日志：

```bash
bash start.sh logs
```

查看 `knowledge_shelf_query` 自身的结构化运行日志（启动、HTTP 请求和处理异常）：

```bash
bash start.sh runtime-logs
```

日志文件位于部署目录的 `logs/knowledge_shelf_query.log`，按 5 MiB 轮转并保留最近 3 个文件；`logs` 与机器人服务的「日志查询」页面相互独立。

新版本异常时回滚：

```bash
bash start.sh rollback
```

回滚会恢复上一个 `.bin` 并重建容器，不需要网络。

## 六、服务重启判定

`restart` 会停止并重建 `knowledge_shelf_query` 容器，可能中断机器人任务；操作前确认设备空闲，并准备重新登录页面。

需要执行 `bash start.sh restart` 或由更新脚本自动重建容器的情况：

- 更新应用包、回滚应用包，或修改应用启动参数。
- 修改 `docker-compose.yml`、`CONFIG_PNP_DIR`、`KNOWLEDGE_DIR`、端口、挂载路径或其他容器环境变量。
- 更换运行时镜像，或修改 Python、Docker CLI、Compose 等运行时依赖。更换镜像时先执行 `pull-runtime`，再执行 `restart`。
- 修改 `config/feishu_rules.json`；规则在服务启动时加载和校验。
- 服务无响应、健康检查失败、启动失败或运行日志持续出现未处理异常。
- `knowledge` 或 `config_pnp` 目录被整体替换、删除后重建或重新挂载。Docker 可能继续绑定旧目录，表现为宿主机有新文件但容器内看不到；重启后还需在页面执行「一键加载」刷新内存数据。

通常不需要重启的情况：只修改已挂载目录中的 knowledge JSON、库位 CSV 或 `config_pnp/config.py`，在页面执行「一键加载」/「重新加载」即可；修改 `config/users.json` 后下一次登录生效。

**更换 Knowledge 根目录才需要重建容器**：把 `KNOWLEDGE_DIR` 改为新的 `model/templates` 根目录后执行 `bash start.sh restart`；同一根目录下更换日期场景只需在页面填写新目录并加载。

快速确认宿主机和容器是否使用同一份目录。「数据加载」页 Knowledge 输入框中的 `knowledge` 表示默认 `/data/knowledge/knowledge`；输入 `.` 时若根下存在默认 `knowledge` 子目录会使用该子目录：

```bash
# 宿主机侧（替换为当前 KNOWLEDGE_DIR）
find /实际/model/templates/knowledge \
  -maxdepth 1 -type f -name '*.json' | wc -l
# 容器侧
docker exec knowledge_shelf_query \
  sh -c "find /data/knowledge/knowledge -maxdepth 1 -type f -name '*.json' | wc -l"
```

两边数量或新文件可见性不一致时，先确认设备空闲，再重启容器并重新加载数据。

## 七、运行时镜像更新

仅以下情况需要更新运行时镜像：

- 修改 `Dockerfile` 或基础镜像。
- Python 主版本或次版本发生变化。
- Docker CLI 或 Docker Compose 版本发生变化。
- 增加需要安装的系统包或第三方 Python 依赖。

开发机执行：

```bash
bash devOps/build_push_aarch64.sh v1.2.0
```

目标设备使用新运行时镜像：

```bash
RUNTIME_IMAGE=hub.noematrix.cn/pharmacy/knowledge_shelf_query_runtime:v1.2.0 \
bash start.sh pull-runtime

RUNTIME_IMAGE=hub.noematrix.cn/pharmacy/knowledge_shelf_query_runtime:v1.2.0 \
bash start.sh restart
```

如需长期使用新版本，将 `docker-compose.yml` 中的默认 `RUNTIME_IMAGE` 版本改为对应版本。

## 八、配置迁移

升级部署目录但需要保留原设备配置时：

```bash
cp -r ../ksq_deploy_v1.2.5/config/. ./config/
cp ../ksq_deploy_v1.2.5/robot_keyboard.env ./robot_keyboard.env
bash start.sh start
```

日常使用 `start.sh update` 时不需要迁移配置。

## 九、命令清单

| 命令 | 用途 | 是否需要网络 |
| --- | --- | --- |
| `./start.sh`（或 `bash start.sh start`） | 替换同名旧容器并启动服务 | 仅本地缺少运行时镜像时需要 |
| `bash start.sh restart` | 重建容器并启动 | 否 |
| `bash start.sh update <文件.bin>` | 更新应用代码 | 否 |
| `bash start.sh rollback` | 回滚上一个应用包 | 否 |
| `bash start.sh version` | 查看应用包版本 | 否 |
| `bash start.sh logs` | 查看日志 | 否 |
| `bash start.sh runtime-logs` | 查看自身服务运行日志 | 否 |
| `bash start.sh stop` | 停止服务 | 否 |
| `bash start.sh pull-runtime` | 拉取运行时镜像 | 是 |
