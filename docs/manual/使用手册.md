# DevOps Toolchain 软件使用说明

## 1. 进入系统

1. 使用浏览器打开管理员提供的地址：`http://<设备IP>:8765`。
2. 在登录页输入管理员提供的用户名和密码；未登录访问任意页面会自动跳转到登录页。
3. 等待「加载中…」消失后，通过左侧菜单选择功能。
4. `DevOps Toolchain` 名称下方显示当前应用包版本；报障时请一并提供该版本号。

账号分为管理员和普通用户两级角色：

| 角色 | 权限 |
| --- | --- |
| 管理员 | 全部操作 |
| 普通用户 | 除以下三类操作外均可正常使用：保存库位编辑、保存设置页配置（工作模式切换除外）、以「导入」方式加载数据 |

- 会话有效期 12 小时，期间持续使用会自动续期；服务（容器）重启后所有会话失效，需重新登录。
- 点击右上角用户名区域可查看当前账号和角色，并执行「退出登录」。
- 普通用户执行受限操作时，页面会提示需要管理员权限，请改用管理员账号登录。

| 菜单 | 功能 |
| --- | --- |
| 仪表板 | 查看当前工单、子任务和处理进度 |
| 数据加载 | 加载、查看或导入药品配置数据 |
| 数据查询 | 查询、筛选、编辑和下载药品数据 |
| 药品下单 | 选择药品并创建工单 |
| 日志查询 | 查看服务日志，启动、重启或停止服务 |
| 设置 | 配置工作模式、下单服务、虚拟键盘和飞书表单 |

## 2. 常用操作顺序

1. 在「设置」中确认当前为**测试**或**生产**模式。
2. 在「数据加载」中点击「一键加载」，或在「本机路径」中手工指定路径加载数据。
3. 在「数据查询」中核对药品和库位信息。
4. 在「药品下单」或「测试下单」中创建工单。
5. 在「仪表板」中查看进度并处理确认提示。
6. 出现异常时，在「日志查询」中查看相关服务日志。

## 3. 数据加载

### 3.1 本机路径

用于查询、编辑、下单等完整功能。

推荐使用「一键加载」：系统自动解析设备 `config_pnp` 目录中的 `config.py`，定位库位表（含按日期命名的 `sku-shelves*.csv`）、不可处理列表、工具映射和闭环吸取列表并完成加载，解析到的路径会回填到表单中。库位表按日期换新文件后，重新执行「一键加载」即可跟随，无需手工修改路径。

需要手工指定路径时：

1. 选择「本机路径」。
2. 核对以下路径：
   - Knowledge 目录
   - 库位表（`sku-shelves*.csv`）
   - 不可处理列表
   - 工具映射
   - 闭环吸取列表
3. 点击「加载数据」。
4. 页面显示加载数量后，点击「进入查询」。

手工填写或「导入」写入的路径优先于 `config.py` 的解析结果；再次执行「一键加载」后恢复以 `config.py` 为准。提示未找到 `config_pnp/config.py` 时，请确认设备的 `config_pnp` 目录已正确挂载，或改用手工路径加载。

如果页面出现「缺少 knowledge」列表：

- 勾选「排除不可处理」，可隐藏无需处理的药品。
- 点击「导出列表 CSV」，导出缺失清单。
- 点击「导出 knowledge 模板 ZIP」，生成待补充的模板文件。

### 3.2 包加载

用于临时查看配置包，不会覆盖本机文件。

1. 选择「包加载」。
2. 选择 ZIP 配置包。
3. 点击「加载查看」。
4. 加载成功后进入「数据查询」。

包加载只支持查看、查询和下载，不支持编辑、药品下单或测试下单。

### 3.3 导入

用于将文件写入当前配置路径。

1. 选择「导入」。
2. 选择 ZIP、JSON、CSV 单文件或多个文件。
3. 点击「导入」。
4. 检查页面显示的写入位置、备份位置和重新加载结果。

支持导入：

- `sku-shelves*.csv`
- knowledge JSON 文件
- 工具映射、闭环吸取、不可处理配置
- `order_config*.json`
- 包含以上文件的 ZIP

同名文件会先备份再覆盖。药品数据导入完成且路径齐全时，系统会自动重新加载；否则需返回「本机路径」手动加载。

## 4. 数据查询

### 4.1 查询和筛选

- 扫码或在「扫码」框输入 69 码、库位，可快速定位记录。
- 在各列表头下方输入条件，可按字段组合筛选。
- 库位可分段输入，数值字段可输入最小值和最大值。
- 点击列表头，可按升序、降序、取消排序循环切换。
- 点击「字段过滤条件」，可选择显示字段；「全部」显示所有字段，「基础列」恢复常用字段。
- 使用页面底部控件切换每页条数或页码。
- 外部文件发生变化后，点击「重新加载」刷新数据。

### 4.2 编辑数据

仅「本机路径」加载支持编辑。

1. 点击「编辑」进入编辑模式。
2. 点击需要修改的单元格。
3. 文本字段修改后按 `Enter` 暂存；选项字段选择后会自动暂存。
4. 完成全部修改后，点击「保存」。
5. 在确认窗口中点击「确定写回」。
6. 如系统提示需要重启相关服务，根据现场情况选择「立即重启」或「稍后手动」。

编辑注意事项：

- `id`、商品编码和药品名称不可编辑。
- 点击正在编辑的单元格以外区域会取消该单元格尚未暂存的内容；文本修改后应先按 `Enter`。
- 多库位药品需先在「库位」列选择目标库位，再修改库位、货架属性或挡板高度。
- 保存时会先备份原文件，再写入修改内容。

### 4.3 下载数据

点击「下载」后，可执行以下操作：

- 下载整包 ZIP。
- 下载 knowledge 文件夹 ZIP。
- 选择并下载配置文件或库位文件。
- 输入商品 ID，下载该商品的 knowledge JSON。
- 在表格行上点击鼠标右键，直接下载该行商品的 knowledge JSON。

## 5. 药品下单

下单前需完成「本机路径」加载，并在「设置」中确认工作模式和下单配置。

### 5.1 选择药品后下单

1. 使用扫码框或列表头筛选找到药品。
2. 点击药品所在行，将其加入待下单列表；再次点击可取消。
3. 多库位药品在「库位」列勾选本次使用的库位。
4. 点击「下单」右侧的 `▼`，检查待下单药品和库位；需要删除时点击对应项的「取消」。
5. 点击「下单」。系统会自动获取 Token 并创建工单。
6. 下单成功后，页面自动进入「仪表板」。当前单未结束时仍可再下一单，第二单进入等待队列；最多同时保留两单，当前单进入完成、失败、取消或人工完成终态后，仪表板自动切换到下一单。

### 5.2 扫码直接下单

在「药品下单」页面扫码并按 `Enter` 时：

- 只匹配到一条药品记录：系统会立即创建工单。
- 匹配到多条记录：系统只显示匹配结果，需手动选择后点击「下单」。
- 未匹配到记录：页面提示「未找到匹配商品」。

只想筛选、不想立即下单时，请输入内容后不要按 `Enter`。

### 5.3 查看工单与下单失败详情

1. 在「下单结果」中输入或保留 `task_id`。
2. 点击「刷新状态」查看工单状态；未结束的工单会继续自动刷新。

下单失败时，页面会保留行内错误，并弹出详细窗口。窗口显示错误摘要、浏览器 HTTP 状态、上游 HTTP 状态、业务码和请求追踪号；展开「上游响应」可查看经过脱敏的原始 JSON。Token、密码、`client_secret` 和 Authorization 等敏感字段不会显示原值。

取消、转人工和人工完成不在下单结果中操作，请前往「仪表板」的门店任务列表，在对应工单行上操作。

转人工后当前单保持在人工处理状态，不会切换到下一单；点击「人工完成」并由 Broker 返回“人工转单完成”后，下一单才会成为当前单。工单总耗时在完成、失败、取消、等待打包、转人工或人工完成时停止，不会继续累加。

系统会拦截与当前进行中工单重复的商品编码或 69 码。无商品编码或库位的药品不能下单。

## 6. 测试下单

从「仪表板」或「药品下单」点击「测试下单」进入。该功能仅在「本机路径」加载后可用。

### 6.1 生成测试药品

1. 点击「配置」。
2. 设置「配置数量」；需要复现相同抽样结果时填写相同的「随机种子」。
3. 根据需要启用闭环吸取、工具和包装类型，并设置目标占比。占比填写范围为 `0` 到 `1`。
4. 点击「生成」。

系统会排除不可处理药品和已在「已下单 SKU」列表中的药品，再按配置生成「待下单 SKU」列表。再次生成会替换当前「待下单 SKU」列表，不会清空「已下单 SKU」列表。

### 6.2 导入、导出和搜索

- 「导入 CSV」会清空上次的待下单和已下单列表，再载入文件内容。
- CSV 只需包含「商品编码」「库位」「69码」任一列，支持 `out_item_id`、`location_code`、`sku_code`、`barcode` 等常见英文表头；名称、库位、工具和包装等字段从当前候选数据自动补全。
- 同一标识对应多个候选时按当前候选顺序取第一条，并在导入结果中显示提示；无法在当前候选数据中匹配的行会跳过。
- 「导出待下单 SKU」和「导出已下单 SKU」分别导出对应列表。
- 搜索框支持按编码、库位、69 码、名称等全部字段筛选。
- 点击列表头可切换升序、降序和取消排序。

### 6.3 提交测试工单

1. 在「待下单 SKU」列表勾选药品，也可点击「全选」选择当前筛选结果。
2. 点击页面上方「下单」。
3. 下单成功后，所选药品移入「已下单 SKU」列表，页面自动进入「仪表板」。

一次提交无论包含一个还是多个 SKU，都计为一个订单。「已下单 SKU」默认按订单批次倒序展示，最新订单在最上方；汇总区分别显示待下单 SKU 数、已下单 SKU 数和订单量。

列表操作：

- 「清空」删除对应列表中的全部记录。
- 在「已下单 SKU」列表勾选记录后点击「恢复」，可将记录移回「待下单 SKU」。
- 「全选」只选择当前搜索结果中可见的记录。

## 7. 仪表板

### 7.1 查看工单

- 「当前工单」显示订单来源、工单号、`task_id`、工单状态和完成进度。
- 同时存在第二单时，「当前工单」显示“下一单等待”标记、下一单订单号和 SKU 数；当前单进入 Broker 终态后自动切换。
- 「当前子任务」显示当前药品、69 码、库位、处理状态和用时。
- 状态流程为：开始处理 → 处理中 → 人工确认 → 结束。
- 「工单子任务」显示每件药品的处理状态。
- 「门店任务」显示当前模式、当前配置门店的 Broker 真实历史任务、总条数和总页数，可按状态筛选、设置每页数量和翻页。
- 当前活动工单在任务列表中标记为「当前」。点击「详情」只查看 Broker 原始详情，不会切换当前工单。
- 「实时事件流」显示最近发生的处理事件。
- 点击「刷新」可立即更新一次状态；停留在该页面时系统会自动刷新。

任务列表不跟随仪表板的快速状态轮询；后端按 Broker 游标取得完整列表后短时缓存，再按页展示。首次进入、调整筛选或分页、手动刷新以及完成工单操作时才查询，其中手动刷新和工单操作会强制更新缓存。

### 7.2 处置工单

测试模式下，「门店任务列表」根据 Broker 最新状态在对应行显示可执行操作：

| 当前状态 | 可执行操作 |
| --- | --- |
| 等待中、已拆单、运行中、等待打包 | 取消任务 |
| 运行中 | 转人工 |
| 人工处理中、人工转单 | 人工完成 |

- 转人工之后 Broker 把工单置为「人工处理中」（`manual_claimed_in_progress`），此时才会出现「人工完成」按钮；点完变成「人工处理完成」（`manual_claimed_completed`），排队中的下一单随即放行。状态不对时按钮不显示，强行提交会返回「当前工单状态 … 不允许人工完成」。Broker 另有一套 `manual_transferred*` 的旧命名，两套都按同样的规则处理。
- 取消任务必须填写取消原因；取消类型默认为人工取消。
- 每次操作都需二次确认。提交期间按钮会禁用，成功后仪表板和任务列表立即刷新。
- 生产模式只允许查看任务列表和详情，不显示或开放这些写操作。

### 7.3 处理确认提示

- 出现确认窗口时，确认现场状态无误后点击「确认」，流程继续。
- 点击「稍后处理」只关闭当前窗口，不会执行确认；之后可点击页面中的「确认处理」。
- 报错提示应先处理现场问题，再执行确认。

### 7.4 自动确认

开启右上角「自动确认」后，系统检测到确认或报错请求时会短暂显示窗口，然后自动确认并继续流程。

自动确认会对所有使用同一服务的浏览器生效。仅在无需人工检查的测试场景中开启，使用完毕后及时关闭。

## 8. 日志查询

### 8.1 查看日志

1. 在「服务」中选择要查看的服务。
2. 进入页面后会自动显示最近约 800 行日志，并像 `docker logs -f` 一样持续追加新日志。
3. 点击「刷新日志」会清空当前显示并重新加载最近日志、建立实时连接。
4. 切换服务时，页面会自动断开旧连接并跟随所选服务的日志和运行状态。

页面显示容器程序的原始日志行，不额外显示 Docker UTC 时间。相同内容的日志不会被去重，会严格按容器输出顺序保留。

如 Docker 日志文件包含 NUL 损坏段，常规 `docker logs` 会在解析损坏记录时停止。页面会保留已读取内容，跳过损坏历史并从当前时刻继续；若 `docker logs` 仍不可用，则自动降级到 `docker attach` 获取新日志。页面不会自动删除或截断历史日志文件。

### 8.2 控制服务

- `Start`：启动所选服务。
- `Restart`：重启所选服务。
- `Stop`：停止所选服务。

点击后需在确认窗口中再次确认。正在执行取药任务时，不要停止或重启相关服务；没有服务管理权限时只使用日志查看功能。

## 9. 设置

### 9.1 工作模式和下单配置

1. 展开「工作模式」。
2. 在顶部开关选择「测试」或「生产」。切换后，系统会立即保存模式并加载对应配置。
3. 核对服务地址、客户、账号信息和 `store_id`。
4. 点击「获取 Token」验证账号配置。
5. 需要选择门店时，点击「获取门店」，在门店列表中选择；系统会自动填写 `store_id`。
6. 点击「保存」。

注意：

- 所有下单、任务查询和仪表板显示均使用当前模式。
- 新环境中测试、生产两套下单配置都默认为空；已有保存值不会被覆盖。客户「—」表示未选择，也可选择大参林、药师帮或漱玉。
- 生产模式下还需核对 ETM 地址。
- 修改下单配置并保存后，应重新点击「获取 Token」。
- 密码或 Secret 已保存且不需要修改时，保持输入框为空。

### 9.2 虚拟键盘配置

1. 展开「虚拟键盘配置」。
2. 点击「刷新设备」，更新可用设备列表。
3. 选择「监听/注入设备」。
4. 如需配置立即生效，开启「保存时重启机器人」。
5. 点击「保存键盘配置」。

重启机器人会中断当前机器人任务，操作前应确认设备处于空闲状态。

### 9.3 飞书表单

飞书表单默认关闭，只有明确开启并保存后才会提交。

1. 展开「飞书表单」。
2. 填写测试场地、App ID、App Secret、`app_token` 和 `table_id`。
3. 「测试人员」需填写人员 `open_id`，不能填写姓名；不需要记录人员时可留空。
4. 点击「同步场地」，从飞书表单更新场地选项。
5. 开启「启用」，然后点击「保存」。

启用后，工单出现人工确认、打包或报错事件时会自动提交表单。需要补交时，先在仪表板确认当前工单，再点击「提交当前工单」。

### 9.4 其他表单

除内置工单表外，还可以接入其他测试表（如「药房功能测试」）。新增表单不需要改程序：在「其他表单」文本框里按 `名称|app_token|table_id` 每行写一个，保存即可。App ID 和 App Secret 与工单表共用。

「自动提交到」用来指定工单内容自动写进哪张表，默认是内置的工单表；选择哪张表，工单结束时就自动提交到哪张。改选其他表后，自动提交的内容**按目标表的结构定制**：系统能推导的字段按目标表的列名自动映射写入，目标表没有的列自动跳过，不会因为字段对不上导致整条记录被飞书拒绝（飞书报 `FieldNameNotFound` / `1254045` 就是这个原因）。选中的表被删掉时会自动退回工单表。

自动写入的内容（查不到就留空，不影响提交）：

| 目标表列名包含 | 写入内容 |
| --- | --- |
| `task_id` | 当前工单的 `task_id` |
| 「开始时间」 | 工单里最早开始处理的时间 |
| 「结束时间」 | 人工确认（工单结束）的时间 |
| 「问题现象」/「问题描述」 | 报错行前 400 后 200 行日志的摘要，仅在工单判定为失败时有内容 |
| `SKU<n>末端工具` | 该 SKU 在工具映射中的推荐工具；工具名不在该列的选项里就不填 |
| 「测试用例id」（关联列） | 用当前工单的 `task_id` 反查「测试下单」里的组号（再次下单按 SKU 编码兜底），再到被关联表里找同名记录；对不上就不选 |
| `SKU<n>` 级联步骤列（识别/吸取/扫码/放置/出库） | 按该 SKU 子任务的执行结论填：成功的 SKU 全部通过（出库推定「正确」）；失败的 SKU 填到失败环节（含）为止、其后留空——与表单「任一环节失败则结束」的规则一致；未执行的 SKU 整链留空 |

失败工单会自动把报错上下文（前 400 行 + 后 200 行日志）渲染成图片，写入附件列「错误日志截图和机器拍照」。附件上传失败（飞书应用缺 `drive/media` 权限）不影响记录写入，提交结果里会附带说明。

注意：级联步骤的结论来自机器人日志与工单状态，个别环节（如出库）没有独立日志信号、由前后阶段推定；如发现与实际不符，直接在飞书里改。如果目标表没有任何可推导的列，这次提交会被记为「空内容」直接跳过。

## 10. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 提示“当前为包加载”，不能编辑或下单 | 到「数据加载」改用「本机路径」加载 |
| 查询、下单页面提示尚未加载数据 | 到「数据加载」完成加载后再进入 |
| 下单按钮不可用 | 先选择有商品编码和库位的药品，并检查下单配置 |
| 获取 Token 或门店失败 | 检查当前模式、服务地址、账号、密码或 Secret |
| 重复药品无法勾选或下单 | 等待当前工单结束，或确认任务状态后再操作 |
| 仪表板显示服务未启动或接口异常 | 到「日志查询」检查相关服务状态和错误日志 |
| 日志提示包含 NUL 损坏段 | 页面会跳过损坏的历史段并继续显示新日志；如需恢复完整历史，再由运维人员轮转日志或重建对应容器 |
| 页面自动跳转登录页，或提示未登录 | 会话已过期（有效期 12 小时）或服务已重启，重新登录即可 |
| 普通用户无法保存编辑、保存配置或使用「导入」 | 该操作仅管理员可用，请改用管理员账号登录 |
| 「一键加载」提示未找到 config_pnp/config.py | 确认设备的 `config_pnp` 目录已正确挂载，或改用本机路径手工加载 |
| 修改后保存按钮仍不可用 | 文本修改后先按 `Enter` 暂存 |
| 飞书提交失败 | 检查是否启用，以及 App ID、App Secret、`app_token`、`table_id` 是否正确 |
| 飞书报 `FieldNameNotFound`（`1254045`） | 目标表缺少要写入的列。现在这类字段会自动跳过，不再整条失败；如果提交结果显示「空内容」，说明「自动提交到」选错了表，改回工单表 |

同一服务的多个浏览器会共享加载数据、设置、自动确认开关和工单状态。避免多人同时编辑数据、切换工作模式或操作同一工单。
