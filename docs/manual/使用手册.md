# DevOps Toolchain 软件使用说明

## 1. 进入系统

1. 使用浏览器打开管理员提供的地址：`http://<设备IP>:8765`。
2. 在登录页输入管理员提供的用户名和密码；未登录访问任意页面会自动跳转到登录页。
3. 等待「加载中…」消失后，通过左侧菜单选择功能。
4. `DevOps Toolchain` 名称下方显示当前应用包版本；报障时请一并提供该版本号。

账号分为管理员和普通用户两级角色：

| 角色 | 权限 |
| --- | --- |
| 管理员 | 全部操作 |
| 普通用户 | 除以下三类操作外均可正常使用：保存库位编辑、保存设置页配置（工作模式切换除外）、以「导入」方式加载数据 |

- 会话有效期 12 小时，期间持续使用会自动续期；服务（容器）重启后所有会话失效，需重新登录。
- 点击右上角用户名区域可查看当前账号和角色，并执行「退出登录」。
- 普通用户执行受限操作时，页面会提示需要管理员权限，请改用管理员账号登录。

| 菜单 | 功能 |
| --- | --- |
| 仪表板 | 查看当前工单、子任务和处理进度 |
| 数据加载 | 加载、查看或导入药品配置数据 |
| 数据查询 | 查询、筛选、编辑和下载药品数据 |
| 药品下单 | 选择药品并创建工单 |
| 日志查询 | 查看机器人等业务容器日志，启动、重启或停止服务；本工具自身运行日志见 8.3 |
| 地图导航 | 查看实时地图与雷达，维护停留点并执行巡逻 |
| 设置 | 配置工作模式、下单服务、虚拟键盘和飞书表单 |

## 2. 常用操作顺序

1. 在「设置」中确认当前为**测试**或**生产**模式。
2. 在「数据加载」中点击「一键加载」，或在「本机路径」中手工指定路径加载数据。
3. 在「数据查询」中核对药品和库位信息。
4. 在「药品下单」或「测试下单」中创建工单。
5. 在「仪表板」中查看进度并处理确认提示。
6. 出现异常时，在「日志查询」中查看相关服务日志。

## 3. 数据加载

### 3.1 本机路径

用于查询、编辑、下单等完整功能。

推荐使用「一键加载」：系统自动解析设备 `config_pnp` 目录中的 `config.py`，定位库位表（支持 `sku-shelves*.csv` 和 `etm_sku_locations_cache*.csv`）、不可处理列表、工具映射和闭环吸取列表并完成加载，解析到的路径会回填到表单中。库位表按日期换新文件后，重新执行「一键加载」即可跟随，无需手工修改路径。

需要手工指定路径时：

1. 选择「本机路径」。
2. 核对以下路径：
   - Knowledge 目录
   - 库位表（`sku-shelves*.csv` 或 `etm_sku_locations_cache*.csv`）
   - 不可处理列表
   - 工具映射
   - 闭环吸取列表
3. 点击「加载数据」。
4. 页面显示加载数量后，点击「进入查询」。

手工填写或「导入」写入的路径优先于 `config.py` 的解析结果；根目录挂载模式再次执行「一键加载」后恢复启动时配置的默认 Knowledge 目录，旧的 `--vfm-app` 兼容模式则继续按 `config.yaml` 解析。启动参数中显式指定的路径（例如 `--knowledge`）始终优先，不会被「一键加载」覆盖。提示未找到 `config_pnp/config.py` 时，请确认设备的 `config_pnp` 目录已正确挂载，或改用手工路径加载。

页面默认只显示和填写当前挂载目录下的**相对路径**，不需要输入 `/data/...` 前缀：

- 标准部署中 Knowledge 目录默认显示为 `knowledge`，表示 `/data/knowledge/knowledge`；可填写 `.` 或根下场景目录，若该目录包含 `knowledge` 子目录会自动使用该子目录，也可直接填写完整的 `.../knowledge` 路径。
- 库位表、工具映射、闭环吸取和不可处理列表相对 `config_pnp`，通常只填文件名，例如 `etm_sku_locations_cache.csv`。
- 需要使用上述目录外的文件时仍可填写容器内绝对路径；宿主机路径不能直接填写。

部署时的 `KNOWLEDGE_DIR` 是 `model/templates` 根目录，挂载到容器 `/data/knowledge`；默认加载根下 `knowledge`，也支持根下任意场景目录。只更新 JSON 或切换同一根目录下的场景时无需重启，重新填写路径或点击「一键加载」即可；更换挂载根才需要重建容器。

文件名无限制：「本机路径」与「一键加载」只看路径是否存在，Knowledge 需为目录、其余四项需为文件，叫什么名字都可以。上面标注的 `sku-shelves*` 等命名只在「包加载」和「导入」两个页签生效（靠文件名识别类型）。

如果页面出现「缺少 knowledge」列表：

- 勾选「排除不可处理」，可隐藏无需处理的药品。
- 点击「导出列表 CSV」，导出缺失清单。
- 点击「导出 knowledge 模板 ZIP」，生成待补充的模板文件。

### 3.2 包加载

用于临时查看配置包，不会覆盖本机文件。

1. 选择「包加载」。
2. 选择 ZIP 配置包。
3. 点击「加载查看」。
4. 加载成功后进入「数据查询」。

包加载只支持查看、查询和下载，不支持编辑、药品下单或测试下单。

### 3.3 导入

用于将文件写入当前配置路径。

1. 选择「导入」。
2. 选择 ZIP、JSON、CSV 单文件或多个文件。
3. 点击「导入」。
4. 检查页面显示的写入位置、备份位置和重新加载结果。

支持导入：

- `sku-shelves*.csv` 或 `etm_sku_locations_cache*.csv`。存在 `sku_id` 时以其关联同名 knowledge；旧格式仍以 `sku_code` 关联。
- knowledge JSON 文件
- 工具映射、闭环吸取、不可处理配置
- `order_config*.json`
- 包含以上文件的 ZIP

同名文件会先备份再覆盖。药品数据导入完成且路径齐全时，系统会自动重新加载；否则需返回「本机路径」手动加载。

## 4. 数据查询

### 4.1 查询和筛选

- 扫码或在「扫码」框输入 69 码、库位，可快速定位记录。
- 在各列表头下方输入条件，可按字段组合筛选。
- 库位可分段输入，数值字段可输入最小值和最大值。
- 点击列表头，可按升序、降序、取消排序循环切换。
- 点击「字段过滤条件」，可选择显示字段；「全部」显示所有字段，「基础列」恢复常用字段。
- 使用页面底部控件切换每页条数或页码。
- 外部文件发生变化后，点击「重新加载」刷新数据。

### 4.2 编辑数据

仅「本机路径」加载支持编辑。

1. 点击「编辑」进入编辑模式。
2. 点击需要修改的单元格。
3. 文本字段修改后按 `Enter` 暂存；选项字段选择后会自动暂存。
4. 完成全部修改后，点击「保存」。
5. 在确认窗口中点击「确定写回」。
6. 如系统提示需要重启相关服务，根据现场情况选择「立即重启」或「稍后手动」。

编辑注意事项：

- `id`、商品编码和药品名称不可编辑。
- 点击正在编辑的单元格以外区域会取消该单元格尚未暂存的内容；文本修改后应先按 `Enter`。
- 多库位药品需先在「库位」列选择目标库位，再修改库位、货架属性或挡板高度。
- 保存时会先备份原文件，再写入修改内容。

### 4.3 下载数据

点击「下载」后，可执行以下操作：

- 下载整包 ZIP。
- 下载 knowledge 文件夹 ZIP。
- 选择并下载配置文件或库位文件。
- 输入商品 ID，下载该商品的 knowledge JSON。
- 在表格行上点击鼠标右键，直接下载该行商品的 knowledge JSON。

## 5. 药品下单

下单前需完成「本机路径」加载，并在「设置」中确认工作模式和下单配置。

### 5.1 选择药品后下单

1. 使用扫码框或列表头筛选找到药品。
2. 点击药品所在行，将其加入待下单列表；再次点击可取消。
3. 多库位药品在「库位」列勾选本次使用的库位。
4. 点击「下单」右侧的 `▼`，检查待下单药品和库位；需要删除时点击对应项的「取消」。
5. 点击「下单」。系统会自动获取 Token 并创建工单。
6. 下单成功后，页面自动进入「仪表板」。当前单未结束时不能再次下单，页面会弹窗提示等待上一单完成。

### 5.2 扫码直接下单

在「药品下单」页面扫码并按 `Enter` 时：

- 只匹配到一条药品记录：系统会立即创建工单。
- 匹配到多条记录：系统只显示匹配结果，需手动选择后点击「下单」。
- 未匹配到记录：页面提示「未找到匹配商品」。

只想筛选、不想立即下单时，请输入内容后不要按 `Enter`。

### 5.3 查看和处理工单

下单成功后自动进入「仪表板」查看状态。下单失败时页面会弹窗显示简要原因。

取消、转人工和完成操作请在「仪表板」的门店任务列表中执行。

转人工后当前单保持在人工处理状态；点击「完成」并由 Broker 返回“人工转单完成”后，工单才会结束。工单总耗时在完成、失败、取消、等待打包、转人工或人工完成时停止，不会继续累加。

系统会拦截与当前进行中工单重复的商品编码或 69 码。无商品编码或库位的药品不能下单。

## 6. 测试下单

从「仪表板」或「药品下单」点击「测试下单」进入。该功能仅在「本机路径」加载后可用。

### 6.1 生成测试药品

1. 点击「配置」。
2. 设置「配置数量」；需要复现相同抽样结果时填写相同的「随机种子」。
3. 根据需要启用闭环吸取、工具和包装类型，并设置目标占比。占比填写范围为 `0` 到 `1`。
4. 点击「生成」。

系统会排除不可处理药品和已在「已下单 SKU」列表中的药品，再按配置生成「待下单 SKU」列表。再次生成会替换当前「待下单 SKU」列表，不会清空「已下单 SKU」列表。

### 6.2 导入、导出和搜索

- 「导入 CSV」会清空上次的待下单和已下单列表，再载入文件内容。
- 选择「组合」导入时，同一组合字段值的 SKU 会整组勾选；提交后仪表盘按相同组合字段和值分段显示子任务。
- CSV 只需包含「商品编码」「库位」「69码」任一列，支持 `out_item_id`、`location_code`、`sku_code`、`barcode` 等常见英文表头；名称、库位、工具和包装等字段从当前候选数据自动补全。
- 同一标识对应多个候选时按当前候选顺序取第一条，并在导入结果中显示提示。
- 无法在当前候选数据中匹配的行也照常导入（保留文件原值，名称、工具、包装等属性留空），尚未加载数据时同样可以导入；商品是否真实存在在提交工单时校验，不存在则弹窗报错。这里留空只影响测试下单列表的显示；下单成功后，仪表板的子任务会用 Broker 带回的名称与库位显示。
- 一行含多个同类标识列时按宽表处理：例如两列「69码」或两列「SKU ID」，每个非空取值各拆成一条药品；不同字段各一列（如一列 SKU ID 加一列 69码）视为同一药品的两种标识，不拆分。
- 组合导入时，「69码」和「SKU ID」列都会为组内每个成员配单独勾选框，可单选某个 SKU 也可整组下单。
- 缺「商品编码/69码」或缺「库位」的行无法下单，提交时会被跳过并在结果中提示数量，仍留在「待下单 SKU」列表。
- 「导出待下单 SKU」和「导出已下单 SKU」分别导出对应列表。
- 搜索框支持按编码、库位、69 码、名称等全部字段筛选。
- 点击列表头可切换升序、降序和取消排序。

### 6.3 提交测试工单

1. 在「待下单 SKU」列表勾选药品，也可点击「全选」选择当前筛选结果。
2. 点击页面上方「下单」。
3. 下单成功后，所选药品移入「已下单 SKU」列表，页面自动进入「仪表板」。

一次提交无论包含一个还是多个 SKU，都计为一个订单。「已下单 SKU」默认按订单批次倒序展示，最新订单在最上方；汇总区分别显示待下单 SKU 数、已下单 SKU 数和订单量。

列表操作：

- 「清空待下单 SKU」或「清空已下单 SKU」会删除对应列表中的全部本地记录，操作前会二次确认。
- 在「已下单 SKU」列表勾选记录后点击「恢复到待下单」，可将记录移回本地「待下单 SKU」；这不会取消或修改已经创建的外部订单。
- 「全选」只选择当前搜索结果中可见的记录。

## 7. 仪表板

### 7.1 查看工单

- 「当前工单」显示订单来源、工单号、`task_id`、工单状态和完成进度。
- 「当前子任务」显示当前药品、69 码、库位、处理状态和用时。
- 状态流程为：开始处理 → 处理中 → 人工确认 → 结束。
- 「工单子任务」显示每件药品的处理状态。
- 「门店任务」显示当前模式、当前配置门店的 Broker 真实历史任务、总条数和总页数，可按状态筛选、设置每页数量和翻页。
- 当前活动工单在任务列表中标记为「当前」。点击「详情」只查看 Broker 原始详情，不会切换当前工单。
- 「实时事件流」显示最近发生的处理事件。
- 点击「刷新」可立即更新一次状态；停留在该页面时系统会自动刷新，有在处理的工单时刷得更密，空闲时自动降频。

子任务的药品名称与库位以 Broker 带回的下单信息为准，处理状态与用时来自机器人日志，两边按商品编码、SKU ID 或 69 码任一命中对应。因此导入的 CSV 即使没有名称和库位列，仪表板仍能显示完整信息。

若临时读不到机器人日志，工单状态、子任务卡片和任务列表照常显示（这些不依赖日志），只有「当前子任务」区会提示「无法读取机器人日志，当前子任务未知」并附具体原因，同时回退显示 Broker 侧的工单状态。出现这个提示时到「日志查询」检查对应服务。

任务列表不跟随仪表板的快速状态轮询。后端按 Broker 游标取得完整列表后缓存 20 秒，再按页展示；缓存过期时先直接返回上一份数据并在后台更新，此时列表说明末尾会出现「· 数据更新中」，下一次刷新就能看到新值。因此任务列表最多可能比 Broker 实际状态滞后一小段时间；需要立即看到最新结果时点「刷新列表」，它会绕过缓存强制重取。完成工单操作后也会强制更新。

自动轮询不会影响按钮可用性：轮询期间「上一页」「下一页」「刷新列表」随时可点，手动操作会中止正在进行的自动请求并立即执行。

### 7.2 处置工单

测试模式下，「门店任务列表」根据 Broker 最新状态在对应行显示可执行操作：

| 当前状态 | 可执行操作 |
| --- | --- |
| 等待中、已拆单、运行中、等待打包 | 取消任务 |
| 运行中 | 转人工 |
| 人工处理中、人工转单 | 人工完成 |

- 转人工之后 Broker 把工单置为「人工处理中」（`manual_claimed_in_progress`），原按钮会变成「完成」；点击后变为「人工处理完成」（`manual_claimed_completed`）。状态不对时按钮不显示，强行提交会返回「当前工单状态 … 不允许人工完成」。Broker 另有一套 `manual_transferred*` 的旧命名，两套都按同样的规则处理。
- 取消任务必须填写取消原因；取消类型默认为人工取消。
- 每次操作都需二次确认。提交期间只禁用被点的那一个按钮，其他任务的按钮仍可使用；成功后仪表板和任务列表立即刷新。
- 生产模式只允许查看任务列表和详情，不显示或开放这些写操作。

### 7.3 处理确认提示

- 出现确认窗口时，确认现场状态无误后点击「确认」，流程继续。
- 点击「稍后处理」只关闭当前窗口，不会执行确认；之后可点击页面中的「确认处理」。
- 报错提示应先处理现场问题，再执行确认。

### 7.4 自动确认

开启右上角「自动确认」后，系统检测到确认或报错请求时会短暂显示窗口，然后自动确认并继续流程。该开关管理员与普通用户均可操作。

自动确认会对所有使用同一服务的浏览器生效。仅在无需人工检查的测试场景中开启，使用完毕后及时关闭。

## 8. 日志查询

### 8.1 查看日志

1. 在「服务」中选择要查看的服务，可选 `robot_workspace_move_test`（机器人作业）和 `percept`（视觉识别）。
2. 进入页面后会自动显示最近约 800 行日志，并像 `docker logs -f` 一样持续追加新日志。
3. 点击「刷新日志」会清空当前显示并重新加载最近日志、建立实时连接。
4. 切换服务时，页面会自动断开旧连接并跟随所选服务的日志和运行状态。

日志窗口高度固定，无论内容多少都不会变化；重新进入页面时保留上次内容，直到新快照到达才整体替换，不再出现白闪。

页面显示容器程序的原始日志行，不额外显示 Docker UTC 时间。相同内容的日志不会被去重，会严格按容器输出顺序保留。

如 Docker 日志文件包含 NUL 损坏段，常规 `docker logs` 会在解析损坏记录时停止。页面会保留已读取内容，跳过损坏历史并从当前时刻继续；若 `docker logs` 仍不可用，则自动降级到 `docker attach` 获取新日志。页面不会自动删除或截断历史日志文件。

### 8.2 控制服务

- `Start`：启动所选服务。
- `Restart`：重启所选服务。
- `Stop`：停止所选服务。

点击后需在确认窗口中再次确认。正在执行取药任务时，不要停止或重启相关服务；没有服务管理权限时只使用日志查看功能。

### 8.3 查看本服务运行日志

页面「日志查询」显示的是机器人等业务容器的日志，不是本工具自身的运行日志。遇到页面接口异常、登录问题、药品任务解析异常或未处理错误时，还需要查看本服务日志。

在部署目录执行：

```bash
bash start.sh runtime-logs
```

该命令会显示最近 200 行并持续跟随新日志。日志文件为 `logs/knowledge_shelf_query.log`，记录服务启动、HTTP 请求、客户端错误和未处理异常堆栈；日志按 5 MiB 轮转并保留最近 3 个文件。退出跟随使用 `Ctrl+C`，不会停止服务。

排查工单中的药品重复时，两类日志要配合查看：

1. 在页面「日志查询」中查看机器人日志，搜索同一任务的 `MedicinePickUpTaskItem` 和 `start process object`。
2. 对照 `code`（机器人内部 `sku_id`）和 `barcode`（药品 69 码），确认是否指向同一个药品。
3. 使用 `runtime-logs` 查看本服务是否记录了解析或接口异常。

如果仪表板同时显示一条带药品名称和 69 码的任务，以及一条名称为 `sku-...` 的任务，通常表示内部 SKU 到 69 码的别名映射没有生效。不要直接手工修改名称或库位；保留对应的机器人日志、本服务日志和工单编号，以便进一步修复映射或合并历史状态。

### 8.4 什么时候需要重启服务

重启会中断当前服务，正在执行取药任务时不要操作。容器重启后浏览器会话也会失效，需要重新登录。

| 情况 | 操作 |
| --- | --- |
| 更新或回滚应用包 `.bin` | 使用 `bash start.sh update <文件.bin>` 或 `bash start.sh rollback`，脚本会重建容器 |
| 修改 `docker-compose.yml`、端口、挂载路径、`CONFIG_PNP_DIR`、`KNOWLEDGE_DIR` 或运行时环境变量 | 在部署目录执行 `bash start.sh restart` |
| 修改运行时镜像、Python、Docker CLI 或 Compose 依赖 | 先切换/拉取对应镜像，再执行 `bash start.sh restart` |
| 修改 `config/feishu_rules.json` | 执行 `bash start.sh restart`，启动时会重新校验规则 |
| 容器无响应、健康检查失败、启动异常或服务接口持续报错 | 先查看 `bash start.sh runtime-logs`，确认现场空闲后执行 `bash start.sh restart` |
| `knowledge` 或 `config_pnp` 目录被整体删除后重新生成、替换或重新挂载 | 执行 `bash start.sh restart` 重新绑定目录，然后在页面执行「一键加载」 |

以下情况通常不需要重启服务：只修改现有目录中的 knowledge JSON、库位 CSV 或 `config_pnp/config.py`；修改后在「数据加载」点击「一键加载」或「重新加载」即可。账号文件 `config/users.json` 修改后也不需要重启，下一次登录时生效。

判断目录是否需要重启：宿主机上能看到新文件，但容器内 `/data/knowledge` 或 `/data/config_pnp` 看不到，或者两边文件数量、更新时间明显不同，说明容器仍绑定旧目录，必须先重启再重新加载数据。

## 9. 地图导航

输入底盘 IP 和端口并连接后，可查看实时地图、雷达扫描与底盘状态。在「底盘操作」中输入“巡逻最高速度”，数值与可填范围均以 `m/s` 显示并由当前底盘确定。该数值在开始巡逻时锁定，只控制巡逻各停留点之间的最高速度，不影响手动导航、回桩或重定位。

## 10. 设置

### 10.1 工作模式和下单配置

1. 展开「工作模式」。
2. 在顶部开关选择「测试」或「生产」。切换后，系统会立即保存模式并加载对应配置。
3. 核对服务地址、客户和账号信息；`store_id` 可以暂时留空。
4. 需要选择门店时，先点击「获取门店」，在门店列表中选择；系统会自动填写 `store_id`。也可以直接手动填写 `store_id`。
5. 点击「获取 Token」验证账号配置。
6. 点击「保存」。

注意：

- 所有下单、任务查询和仪表板显示均使用当前模式。
- 新环境中测试、生产两套下单配置都默认为空；已有保存值不会被覆盖。客户「—」表示未选择，也可选择大参林、药师帮、漱玉或穹彻智能。
- 生产模式下还需核对 ETM 地址。
- 修改下单配置并保存后，应重新点击「获取 Token」。
- Token 有效期间状态点保持绿色，切换页面后返回仍会恢复；Token 到期或修改下单配置后恢复为灰色。
- 密码或 Secret 已保存且不需要修改时，保持输入框为空。

### 10.2 虚拟键盘配置

1. 展开「虚拟键盘配置」。
2. 点击「刷新设备」，更新可用设备列表。
3. 选择「监听/注入设备」。
4. 如需配置立即生效，开启「保存时重启机器人」。
5. 点击「保存键盘配置」。

重启机器人会中断当前机器人任务，操作前应确认设备处于空闲状态。

### 10.3 飞书表单

飞书表单默认关闭，只有明确开启并保存后才会提交。

1. 展开「飞书表单」，填写 App ID 和 App Secret。
2. 点击「新增表单」，填写表单名称、`app_token` 和 `table_id`。填写规则默认选择「机器人测试表单」。
3. 可继续新增多个表单，然后在「当前表单」中选择本次自动提交的目标。
4. 按需配置异常 AI 分析，开启「启用」，然后保存。

程序按 `Robot Log -> Log Parser -> Event Builder -> AI Analyzer -> Form Builder` 处理。
测试用例 ID、开始/结束时间、task_id、各 SKU 的识别/抓取/扫码/出库/放置结果和截图由程序确定。
只有 Warning、Timeout、Exception、Error、Failed、Retry 或 Recover 等异常事件才调用 AI，
AI 仅生成问题现象、一级分类和二级分类。正常成功工单不调用 AI。

发送给 AI 的内容仅包含任务状态、SKU 结果和最多 20 条结构化异常事件，不包含完整日志。
AI 返回值必须通过 50 字长度和固定分类枚举校验；接口未配置或输出无效时，三个 AI 字段留空并标记需人工检查，其余确定性字段仍可提交。

启用后，工单进入打包、报错或完成确认阶段时自动提交。需要补交时，确认仪表板当前工单后点击「提交当前工单」。目标表不存在的列会跳过；单选值不在飞书实际选项中也会留空，避免整条记录被拒绝。后续表单字段不同，只需增加对应填写规则并在表单配置中选择，不改提交链路。

## 11. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 提示“当前为包加载”，不能编辑或下单 | 到「数据加载」改用「本机路径」加载 |
| 查询、下单页面提示尚未加载数据 | 到「数据加载」完成加载后再进入 |
| 下单按钮不可用 | 先选择有商品编码和库位的药品，并检查下单配置 |
| 获取 Token 或门店失败 | 检查当前模式、服务地址、账号、密码或 Secret |
| 重复药品无法勾选或下单 | 等待当前工单结束，或确认任务状态后再操作 |
| 仪表板显示服务未启动或接口异常 | 到「日志查询」检查相关服务状态和错误日志 |
| 仪表板提示「无法读取机器人日志，当前子任务未知」 | 工单状态与子任务卡片仍可用；到「日志查询」确认 `robot_workspace_move_test` 是否在运行，必要时重启该服务 |
| 任务列表状态比实际滞后，或末尾显示「数据更新中」 | 列表有 20 秒缓存，过期时先返回旧数据并在后台更新；需要最新结果时点「刷新列表」强制重取 |
| 同一药品在仪表板显示两条，另一条名称是 `sku-...` | 订单数据使用 69 码，机器人日志可能使用内部 SKU；按「8.3 查看本服务运行日志」同时检查两类日志中的 `code`、`barcode` 映射，并保留日志和工单编号，不要手工改名 |
| 日志提示包含 NUL 损坏段 | 页面会跳过损坏的历史段并继续显示新日志；如需恢复完整历史，再由运维人员轮转日志或重建对应容器 |
| 页面自动跳转登录页，或提示未登录 | 会话已过期（有效期 12 小时）或服务已重启，重新登录即可 |
| 普通用户无法保存编辑、保存配置或使用「导入」 | 该操作仅管理员可用，请改用管理员账号登录 |
| 「一键加载」提示未找到 config_pnp/config.py | 确认设备的 `config_pnp` 目录已正确挂载，或改用本机路径手工加载 |
| 修改后保存按钮仍不可用 | 文本修改后先按 `Enter` 暂存 |
| 飞书提交失败 | 检查是否启用，以及 App ID、App Secret、`app_token`、`table_id` 是否正确 |
| 飞书报 `FieldNameNotFound`（`1254045`） | 检查当前表单和填写规则是否匹配；程序只写入飞书实际存在的列 |

同一服务的多个浏览器会共享加载数据、设置、自动确认开关和工单状态。避免多人同时编辑数据、切换工作模式或操作同一工单。
