# 项目功能清单

## 1. 文档范围与阅读说明

本项目 `knowledge_shelf_query`（页面名称 DevOps Toolchain）是面向药房自动化现场的数据查询、测试下单、订单跟踪、机器人操作与设备运维工具。

本文按当前工作区的正式页面、实际路由和业务调用链整理，覆盖用户功能、后台能力、命令行及部署维护入口。它是功能盘点，不是新增需求、接口参数手册或现场验收报告；没有通过本次整理实际操作机器人、提交订单、上传飞书或执行部署。

- 正式界面以 [shell.html](../ksq/web/templates/shell.html) 及其加载的脚本为准。
- 后台入口以 [应用组装](../ksq/web/app.py)、[公共请求处理](../ksq/web/handlers.py) 和 [业务路由](../ksq/web/routes/) 为准。
- 历史说明与当前调用链不同的地方，在第 17 节单独说明；旧函数存在不代表正式流程仍在使用。
- 运行镜像当前默认版本为 `v1.2.0`；应用版本由 `.bin` 构建参数决定，源码运行默认显示 `dev`，两者不能混为一个版本号。
- 详细操作另见 [使用手册](manual/使用手册.md)、[部署操作文档](manual/部署操作文档.md) 和 [架构与验证说明](architecture.md)。

## 3. 登录、权限与共享状态

### 3.1 账号和通用界面

- 用户名/密码登录，展示当前账号、显示名称及角色，支持退出登录。
- 未登录访问业务页面跳转登录页；未登录业务 API 返回 `401`。
- 账号保存在 `users.json`；支持通过文件维护账号、角色和密码，没有独立的网页用户管理模块。
- 明文密码在读取时迁移为 PBKDF2 加盐哈希；后续登录重新读取账号文件，无需重启即可使用更新后的凭据。
- 会话采用内存存储，12 小时滑动续期；服务重启需重新登录。修改账号文件不等同于立即撤销所有旧会话。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；文件、终端、机械臂和桌面入口还有相应的来源校验。
- 通用界面提供侧栏折叠、页面切换、版本显示、加载状态、成功/失败提示、确认弹窗及结构化接口错误展示。
- `/api/health` 无需登录，报告工具服务及版本；它不代表 Broker、机器人、Docker 或飞书均可用。

- 已加载数据、当前工作副本、工作模式、设置、测试清单、最新展示订单和自动确认开关是服务级共享状态，不按浏览器分别维护。

- 管理员也不能绕过生产模式禁止下单、运动中禁止改图等业务限制。

## 4. 数据加载、校验与工作副本

### 4.1 数据组成

| 数据 | 用途 |
| --- | --- |
| Knowledge JSON 目录 | 药品知识属性；按药品标识关联在架记录 |
| 库位 CSV | 在架 SKU、商品编码、69码、药名、物理库位、货架属性、挡板高度等 |
| 不可处理 JSON/设备限制 | 标记不可处理 SKU，叠加设备货架、层、库位限制 |
| 工具映射 JSON | SKU 使用的抓取工具 |
| 闭环吸取/抓取策略 JSON | 是否闭环等策略标记 |
| 下单配置 JSON | Broker 配置，属于应用配置而非药品 Knowledge |

支持 `sku-shelves*.csv`、`etm_sku_locations_cache*.csv` 及适配的 `goods-locations.csv`；不可处理文件兼容 `unavailable_obj` 与旧拼写 `unavailabel_obj`。

### 4.2 加载方式

- **本机路径加载**：手工填写 Knowledge、库位和附加配置路径；这里的“本机”是工具服务所在设备，不是访问浏览器的电脑。
- **一键加载**：解析设备 `config_pnp/config.py`，自动定位相关数据；只做 AST 解析，不执行该 Python 文件。缺失 `config.py` 时明确报错。
- **Knowledge 场景选择**：以 `templates` 挂载根目录为基准，可选根下场景目录或 Knowledge 子目录；符合结构时自动定位 `knowledge` 子目录。
- **本地/云库位切换**：云模式仅由后台从设备本机 `http://127.0.0.1:12005/api/v1/sku/locations` 获取库位 CSV；Knowledge 和其他配置仍为本地文件。
- 云模式禁用本地库位路径填写，切回本地恢复路径；重新加载沿用上次成功的数据来源。云下载或校验失败不静默改用本地库位。
- **ZIP 包加载**：上传数据 ZIP 后查询和导出；不是完整编辑/下单数据源。
- **文件导入**：管理员可导入支持的单个/多个 JSON、CSV 或 ZIP，识别 Knowledge、库位、附加配置与下单配置；按类型合并/替换相应内容并反馈结果。
- **重新加载**：从当前来源重新构建工作副本，刷新查询数据和相关状态。

### 4.3 数据源能力边界

| 当前数据源状态 | 在架查询/数据导出 | 库位编辑 | 创建订单 | 测试清单写操作 |
| --- | --- | --- | --- | --- |
| 未加载 | 无当前业务数据 | 不可用 | 不可用 | 不可用 |
| ZIP 包模式 `bundle` | 可用 | 不可用 | 不可用 | 不可用 |
| 路径型数据源 `paths` | 可用 | 管理员可用 | 测试工作模式可用 | 可用 |

- 一键、本地/云路径加载属于 `paths`；文件导入后的能力以返回的 `load_method/capabilities` 为准。
- 测试清单写操作包括配置保存、生成、CSV 导入、标记已下单、恢复和清空；这些 HTTP 入口均要求 `paths`。
- 已存在测试清单的读取/导出与清单写入是不同接口，不能由“没有加载数据”推断所有页面都不可访问。
- 文件管理、终端、机械臂、日志和地图等功能不以药品数据加载为前提。

### 4.4 加载进度和校验报告

- 显示上传、复制、解析、备份切换等阶段进度；无法计算总量的阶段显示等待状态。
- 统计在架 SKU、库位行、Knowledge 字典、已匹配/缺失 Knowledge、多库位数量及耗时。
- 报告重复 Knowledge、同标识内容冲突、文件名与标识不一致、库位合并冲突、库位缺字段及跳过的文件。
- 同标识多条 Knowledge 以首条作为关联值并报告问题，不静默制造多份商品。
- 跳过辅助文件 `block.json`、`bookshelf.json`、`bottle cap.json` 及不具药品标识的合法辅助 JSON；损坏 JSON 不作为普通辅助文件吞掉。
- 缺少部分甚至全部 Knowledge 字典时，仍可按有效在架记录查询；缺失属性显示 `-`。
- 缺失 Knowledge 列表支持排除不可处理项、导出 CSV、生成待补全 Knowledge 模板 ZIP。
- 兼容 `sku_id` 关联及旧 `sku_code` 数据；多库位不简单压成一个下单位置。

### 4.5 工作副本和备份

- 数据统一使用 `data/current/knowledge`、`data/current/config_pnp` 工作副本，不直接修改源 Knowledge/config_pnp 文件。
- 新副本复制、解析、校验成功后才切换；失败保留当前有效数据。
- 上一份工作副本移入 `data/backups/YYYYMMDD_HHMMSS_ffffff`。
- 启动补清理、每日服务本地时间 `00:00` 清理旧备份；保留当天备份、最新一份历史备份和 `data/current`。
- 库位编辑落在工作副本中。重新加载本机源文件会覆盖这些修改，需保留时先导出。

依据：[数据路由](../ksq/web/routes/data.py)、[数据服务](../ksq/data/service.py)、[数据集解析](../ksq/dataset.py)、[数据能力](../ksq/data/state.py)、[工作副本与备份](../ksq/data/storage.py)。

## 5. 数据查询、编辑与导出

### 5.1 查询展示

- 以在架 SKU 为主体，不把全部 Knowledge 文件无条件展示为在架药品。
- 基础列：`id`、69码、商品编码、药品名称、库位、货架属性、使用工具、是否闭环、是否不可处理、挡板高度。
- 扩展列来自实际 Knowledge 字段，可展示包装、尺寸、重量、材质、表面结构、条码等；未提供的字段不凭空补造。
- 支持输入/扫码识别药品标识、69码和库位，识别和规范化支持的库位码格式。
- 按列组合筛选：文本、枚举、数值最小/最大值、货架/层/格分段库位。
- 支持排序升序/降序/取消、列显示选择、清除筛选、结果数量和分页；可选择每页 50/100/200/500 条。
- 多库位记录可展开对应库位；库位相关属性按目标库位处理。

### 5.2 编辑范围

- 仅管理员、完整数据源下可编辑：**库位、货架属性、挡板高度**。
- 多库位记录先选择目标库位；输入值经过对应校验和格式处理。
- 修改有暂存与确认落盘步骤，界面显示未保存状态及保存结果。
- Knowledge 属性、工具映射、不可处理、闭环配置不提供表格内直接编辑。
- 页面保存不是向设备原始配置目录发布，也不会自动把结果同步到云库位服务。

### 5.3 导出与下载

- 下载当前数据整包 ZIP。
- 下载完整 Knowledge 目录 ZIP。
- 列出并下载当前可导出的库位和配置文件。
- 按药品标识或记录右键下载对应 Knowledge JSON。
- 导出缺失 Knowledge 清单 CSV 和待补全模板 ZIP。
- 测试清单另有待下单/已下单 CSV 导出，见第 7 节。

依据：[查询数据组装](../ksq/web/pages.py)、[正式查询组件](../ksq/web/static/catalog.js)、[编辑工作区](../ksq/data/workspace.py)。

## 6. 药品下单与 Broker 集成

### 6.1 页面下单流程

- 查询/筛选药品，选择物理库位，加入或移除待下单项目后提交。
- 支持扫码后按 Enter；匹配单条且符合选品条件时可直接下单，多条结果时先筛选选择。
- 提交执行本地预检、Token 获取、Broker 创建、结果反馈，成功后进入仪表板查看最新订单。
- 页面选品按可用商品标识和物理库位构造下单行；多库位需要明确选择。
- 创建订单要求 `paths` 数据源和测试工作模式；生产工作模式禁止创建订单，包括测试页面发起的创建。
- 测试工作模式仍会向配置的真实 Broker 提交请求，不是模拟执行或干运行。

### 6.2 请求构造和客户适配

- 自动生成订单标识及时间、订单来源前缀，按客户组合商品字段、金额字段、业务模式及图片上传标记。
- 商品标识按 `out_item_id > sku_id > sku_code > record_id` 等已有数据优先级解析；数量必须为有效的正整数。
- 物理库位用于展示和选品；`customer_location_code` 非空时原样作为 Broker 库位码，保留前导零和连字符；为空时沿用物理码去连字符的兼容规则。
- 配置可填写任意客户字符串；已内置下列 profile，未知客户走默认规则。

| 客户 | 来源支持 | 请求差异 |
| --- | --- | --- |
| 默认/未知客户 | 美团、淘宝闪购、京东、抖音 | 基础商品字段，包含金额，要求库位 |
| 大参林 `dashenlin` | 基础来源 + 大参林健康、淘宝闪购滋补店、企健网、智慧E保 | 批号、效期、价格、厂家、剂型、批准文号等扩展字段；默认等待打包模式 |
| 药师帮 `yaoshibang` | 基础来源 | 名称、规格、厂家、批准文号等；需要零售单号，默认图片上传 |
| 漱玉 `shuyu` | 基础来源 + 漱玉小程序 | `item_name/specification` 字段，省略金额；后台请求构造不强制库位 |
| 桂中大药房 `lzgzdyf` | 基础来源 | 名称、规格、厂家、批准文号等；默认拣选模式 |
| 穹彻智能 `noematrix` | 基础来源 | 需要零售单号，默认拣选模式和图片上传 |

漱玉的“后台不强制库位”是请求 profile 能力，不表示当前选品页面及测试清单页面已全面支持无物理库位下单。

### 6.3 预检、重试与错误反馈

- 带商品明细的预检检查工作模式、配置、来源和商品字段；不取 Token、不创建外部订单。
- Token 缓存及无效凭据刷新重试；订单号冲突业务码 `4601` 会重新生成订单号重试一次。
- 创建请求超时后查询 Broker 任务列表核实是否已创建，无法确认时提示不要重复提交，不盲目重发。
- 成功结果包含 `task_id`、请求体、Broker 响应及本地展示会话；缺少 `task_id` 不按正常成功注册。
- 失败返回错误摘要、业务响应、缺失字段及相关不可处理项说明。
- “不可处理”会用于选品/说明，但创建接口不是仅凭这个标记就额外拒绝所有请求。
- 新订单主流程交由 Broker 判断接单与并发，成功后更新最新展示订单；不使用历史本地 10 单 FIFO 作为当前创建上限。

依据：[订单服务](../ksq/order/service.py)、[请求构造](../ksq/order/payload.py)、[客户配置](../ksq/order/config.py)、[活动订单](../ksq/order/active.py)。

## 7. 测试下单与清单管理

### 7.1 测试选品生成

- 配置目标数量、随机种子，按闭环、工具类型、包装类型及目标比例选择候选。
- 支持各选品维度开关及“全部”类别，展示候选数量、生成数量、分布和不足数量。
- 排除不可处理候选及已下单列表中的对应 SKU/库位；按现有选择策略分层选取、补足，不超过目标数量。
- 生成操作替换待下单列表，保留已下单记录及批次；同一数据及种子可用于复现选品。

### 7.2 CSV 导入

- 支持原行模式和指定组合字段的组合模式。
- 兼容中英文表头、商品多种标识、同类宽表多商品拆分，按候选数据补全工具、包装等属性。
- 支持未匹配到候选的有效行保留，反馈歧义/解析错误；不把“未匹配”直接当成导入失败。
- 保留 CSV 列、原始顺序及组合信息，组合可整组选中，也可选单个 SKU。
- 导入会重建待下单列表并清空原已下单和批次记录；页面提供确认提示。
- Web 导入入口仍要求完整数据源，不能因为底层解析可不依赖候选，就理解为未加载时也可使用该入口。

### 7.3 清单、导出和提交

- 待下单/已下单分栏，支持全字段搜索、排序、当前筛选全选/取消及单项/组合选择。
- 分别导出两个列表；已下单 CSV 带下单时间、订单号等元数据。
- 首次提交成功后，将真正提交的行移入已下单，登记 `task_id`、订单号、时间及批次；本地订单统计按批次而非 SKU 数计算。
- 缺少有效商品标识或物理库位的行不进入当前页面提交载荷；混合选择时仅同步真正提交的行，其余仍留在待下单。
- 支持已下单行内再次下单及勾选已下单项目再次下单；创建新 Broker 订单，不重新搬动两个列表，也不新增该清单的搬移批次。
- 支持已下单恢复至待下单，以及分别清空列表；恢复/清空仅调整本地清单，不取消、撤销或修改已创建的 Broker 订单。

### 7.4 创建成功后的同步恢复

- Broker 创建和本地“标记已下单”是两个步骤；后者支持身份核对与幂等重试。
- 网络失败、服务端错误或响应解析失败时可重试列表同步。
- 同步仍失败则记录待恢复任务；再次点击提交只同步既有订单，不再次创建订单。
- 待恢复期间阻止会破坏对应清单的生成、导入、清空等操作，降低重复下单风险。

依据：[测试订单路由](../ksq/web/routes/test_orders.py)、[清单服务](../ksq/order/test_service.py)、[选品与导入](../ksq/test_order_select.py)、[测试页面](../ksq/web/static/test-order.js)。

## 9. 地图查看、导航与巡逻

### 9.1 连接和实时地图

- 配置底盘 HTTP 地址/IP 和端口，连接思岚/Slamware 系列底盘；默认导航接口端口 `1448`。
- 查看机器人信息、地图图像和元数据、位姿、航向、电量、充电状态、定位质量及当前动作。
- 展示机器人、充电桩、POI、虚拟墙、轨道、区域等地图元素。
- 展示雷达障碍点、观测区域及短时扫描轨迹，提示定位质量、数据延迟和过期状态。
- 支持缩放、平移、跟随机器人、重置视图、手工刷新、自动更新及地图/事件区域布局调整。
- 获取精确坐标与角度，地图点击位置可用于导航或保存 POI。

### 9.2 POI、导航与健康

- POI 查看、新增、删除，作为导航目标或加入巡逻队列。
- 指定目标导航、回桩充电、重定位、取消/停止当前动作。
- 查询动作详情、规划路径、剩余路径和里程点。
- 健康状态及错误列表：原因、错误 ID、描述、错误码、等级、部件、故障类型、设备 ID。
- 管理员可确认后清除底盘错误；清错不等于物理故障已排除。

### 9.3 巡逻规划和执行

- 有序停留点队列，最多 32 点；支持循环、速度设置、规划、开始、暂停、继续和停止。
- 自由导航与轨道优先两种模式；轨道优先使用定向虚拟轨道，需要至少两个不同点。
- 相邻停留点生成引导线段，循环模式补上末点到首点；规划可复用未改变的队列/轨道。
- 必须先规划再执行。规划阶段不移动机器人，可预览真实当前位置到首点的搜路结果。
- 速度以设备最大速度为依据限制在 10%～100%，默认 80%，界面可显示 m/s。
- 改动队列、坐标、模式、连接或执行其他导航等会使规划失效；首次启动相对规划起点偏移超过允许阈值时要求重新规划。
- 巡逻中显示当前动作、停留点与剩余路线；连接切换、建图和运动冲突有保护。

### 9.4 轨道清理

- 可在列表或地图中选轨道、全选、高亮并确认删除；运动中禁止删除。
- 自动清理仅针对本巡逻功能创建且未被编辑的带标记旧轨道，不清理手工、被修改或无标记旧轨道。
- 删除轨道不是自动保存整个地图到固件，需结合建图上传/保存流程。
- 自动生成的直线是导航引导，不是已经验证可通行的避障路线；实际搜路和避障由底盘能力决定，不保证预先得到任意两个停留点间的完整路线。

依据：[地图路由](../ksq/web/routes/map.py)、[底盘服务](../ksq/robot/service.py)、[地图页面](../ksq/web/static/map.js)。

## 10. 建图、地图对象与手动遥控

### 10.1 建图和 STCM 生命周期

- 新建、清空、重命名地图，显示当前建图状态及未保存变更。
- 开始采集、暂停、继续、结束采集；自动闭环开关。

- 备份按底盘连接地址隔离；覆盖前可备份，清空当前地图不等于删除历史备份。

- 超时或结果不确定时保留脏状态/不确定标记，并限制后续导航，需要明确恢复或重新导入。
- 建图、导航和巡逻有互斥条件，运动中不允许直接覆盖地图；界面提醒云托管地图可能覆盖本地修改。

### 10.2 正式页面可编辑对象

| 对象 | 能力 |
| --- | --- |
| POI | 位置、名称、方向等查看及维护 |
| 充电桩/回桩点 | 查看及部署相应位姿 |
| 虚拟墙 | 端点创建、修改、删除 |
| 虚拟轨道 | 直线轨道创建、修改、删除及相关属性 |
| 禁行区域 | 矩形区域及逃逸距离 |
| 危险区域 | 矩形区域及限速 |

- 提供前、后、左、右及停止，按住移动，释放停止。

- 速度恢复未确认时阻止后续导航，避免把不确定限速状态继续带入自动运动。
- **遥控没有自动避障；页面停止不是硬件急停。** 必须现场确认通道、人员和机器人安全。

## 13. 文件管理、交互终端与远程桌面

### 13.1 文件管理

- 展示实际主机名、系统账号、环境、主目录及当前目录。
- 主目录、输入绝对路径、上级目录、刷新、当前目录搜索及显示隐藏文件。
- 显示文件/目录名称、类型、大小、修改时间及符号链接状态。
- UTF-8 文本预览最多 256 KiB；PNG/JPEG/GIF/WebP 图片预览上限 20 MiB；不执行上传的 HTML/SVG。
- 多文件、目录上传并保留层级，单文件上限 2 GiB；不覆盖同名文件，不保留不完整文件。
- 批量上传失败时报告结果，之前成功的文件保留；浏览器目录上传不包含空目录。
- 文件流式下载，目录打包 ZIP 下载并保留空目录；目录打包限制原始大小 2 GiB、100000 项，不收集符号链接和特殊文件。
- 单次目录展示上限 10000 项，超限要求缩小目录范围。
- 文件、目录和符号链接重命名；只改当前目录中的名称，不覆盖目标，不等同于跨目录移动。
- 没有专用网页文件删除或在线文本编辑器；终端可执行什么仍取决于系统账号权限。

### 13.2 浏览器终端

- Linux PTY 交互 Shell，支持输入输出、方向键、Tab、Ctrl+C、终端尺寸调整及交互式命令。
- 每个登录会话最多 2 个终端，服务最多 8 个，输出缓冲约 1 MiB；失联终端有空闲回收。
- 文件目录卡片与终端独立，浏览目录不会自动在 Shell 执行 `cd`。
- 切换侧栏保持连接；断开、Shell 退出或连接失败时清理终端显示，文件目录不随之清空；重新连接从主目录开始。
- 退出工具登录关闭对应终端，服务关闭时清理终端资源。

### 13.3 宿主机连接与桌面

- 源码运行使用服务进程系统账号；标准 Docker 部署由宿主机连接进程执行文件和终端操作。
- 宿主机连接通过权限受限的 Unix socket，不另开放网络端口；不可用时明确报错，不回退到容器文件系统。
- 宿主机连接仅需 Python 3.8+ 标准库；默认使用部署启动账号，`sudo` 场景按脚本处理原账号。
- 支持 noVNC/TigerVNC 虚拟桌面，通过同一工具 IP、端口和登录会话访问图形程序；宿主机不要求连接显示器。
- 首次桌面安装由部署脚本提供，仅支持 Debian/Ubuntu；已有外部桌面可配置 `KSQ_DESKTOP_URL`。
- 宿主机重启后需恢复本机连接进程；开机自启需接入宿主机服务管理器，项目不承诺默认已安装系统服务。

依据：[文件与终端服务](../ksq/web/files_api.py)、[文件页面](../ksq/web/static/files.js)、[桌面服务](../ksq/web/desktop.py)、[宿主机启动脚本](../deploy/standalone/host-files.sh)。

### 14.1 现场设置

- 测试/生产工作模式切换，分别使用 `order_config.json`、`order_config.prod.json`；切换会清理当前订单展示会话等关联状态。
- Broker 地址、客户、client 凭据、门店选择/手填 ID、订单来源；提供获取 Token 和连接反馈。
- 客户默认业务模式、图片上传等由 profile 自动补充，不要求现场逐项填写全部请求字段。
- 生产 ETM 地址、虚拟键盘设备及环境同步，保存时可选择重建机器人容器。
- 飞书自动提交开关、应用凭据、多表单增删、目标表单选择、规则选择。
- 支持粘贴多维表格链接解析 `app_token/table_id`。
- 可选 OpenAI 兼容 AI 的开关、接口、模型及 Key 配置；这些配置不等于已启用外部分析。

### 14.2 飞书自动/手动提交

- 流程：机器人日志按任务范围截取 → 解析结果 → 结构化异常事件 → 可选 AI → 对照真实表字段 → 生成记录 → 提交飞书多维表格。
- 自动触发覆盖打包/错误提示以及成功、失败、取消、转人工等可识别订单结果。
- 自动提交开关默认关闭；**手动提交是独立的明确动作，不受自动开关关闭的限制**。
- 支持预览拟填字段、元数据、缺失/跳过列及异常情况；预览不创建记录或上传截图，但会读取飞书表字段，启用 AI 时也可能请求 AI。
- 程序确定任务/用例标识、时间和 SKU 识别、抓取、扫码、放置等结果，适配实际表列和单选枚举。
- 非成功订单可生成并上传相关日志截图；成功订单即使有已恢复警告，也不附错误日志截图。
- 按订单号优先、否则任务 ID 去重，结合进程内记录和订单提交状态防重复。
- 提交中状态有过期处理，自动失败有冷却；提交异常记录错误而不让整个仪表板轮询崩溃。
- 去重是当前进程/保留订单状态范围的保护，不是跨所有设备和历史订单的全局唯一事务保证。
- 表单规则为 JSON，启动时校验；部署支持外部规则文件，替换后重启生效。

### 14.3 AI 能力边界

- 只辅助异常现象、一级/二级分类及人工检查标记，不生成订单事实，也不是通用聊天机器人。
- 正常成功且无异常事件时不调用 AI；失败/未知结果或存在异常事件时才考虑调用。
- 输入主要为结构化任务结果、SKU 阶段状态和最多 20 条异常事件，不发送整个未裁剪日志作为分析输入。
- 异常描述最多 50 字，分类受固定枚举校验；重试恢复的异常注明“重试后恢复”。
- 未启用、未配置 Key、请求失败时分析字段留空并提示人工检查；输出校验失败时保留可用部分、清空非法分类并标记人工检查。
- 使用该能力会向配置的外部服务发送上述任务/异常数据，需由现场确认数据处理授权。

### 15.1 源码和数据包入口

| 入口 | 能力 |

### 15.2 交付物与构建

| 入口/产物 | 能力 |
| --- | --- |
| `python deploy/build_app_bin.py <版本>` | 将 Python 源码、模板、静态资源和内置规则构建成 `.bin` 应用包；支持 `--output` |
| `.bin` 校验及启动 | ZIP 完整性、必要文件检查、SHA256；按摘要缓存解包，构建清单提供页面版本 |
| `bash deploy/make_package.sh <版本>` | 生成标准 `ksq_deploy_<版本>.tar.gz`，带启动脚本、Compose、应用包和干净初始配置 |

- 日常代码更新可仅交付 `.bin`；依赖或挂载/启动方式变化时仍需同步镜像、脚本及 Compose。
- 构建推送脚本会影响镜像仓库，属于发布动作，本次功能盘点未执行。

### 15.4 状态维护与持久化边界

- 应用启动比较版本标记；首次无标记或版本变化时备份并重置 `test_order_state.json`、`dashboard_active_order.json`、`order_config.json`、`order_config.prod.json`。
- 保留 `dashboard_settings.json` 中的设置并更新版本标记；`users.json` 不在这组重置范围内。
- 同版本普通重启不触发版本重置；但显式 `reset-state`、部署 `update`、开发脚本 `restart` 另有重置逻辑。
- 回滚是应用代码回滚，不等于恢复之前的订单、配置和业务状态；版本变化仍可能触发重置。
- 标准 Compose 持久化指定配置、账号、规则、数据副本和自身日志，并挂载设备数据、键盘环境文件和 Docker socket。
- 地图设置、POI 缓存、`robot_mapping_backups` 等本地文件未在当前标准 Compose 中逐一挂载，不能笼统承诺所有地图本地状态在容器重建后保留；重要 STCM 应导出，需长期保留的目录另行配置持久化。
- 更新/回滚需要重建容器，会中断服务并使登录会话失效，不是零停机热更新。

## 17. 历史兼容、未开放能力与核对结论

1. **旧本地订单队列**：代码仍有 10 单队列结构、注册/容量/推进函数及兼容测试，但当前创建主链路使用最新订单登记，接单与并发交给 Broker。不能继续将“最多 10 单、旧单未结束拦截、重复 SKU 拦截”当成当前主流程承诺。
2. **生产模式**：禁止创建订单及相应 Broker 写操作；不是全站禁止写入。管理员也不能通过正常订单入口突破该模式限制。
3. **测试 CSV 导入**：底层解析允许候选缺失或未匹配，但 Web 写入口要求已加载 `paths`，包模式/未加载不可用。
4. **无库位下单**：漱玉后台 profile 不要求库位，当前页面选品/测试行过滤仍有物理库位条件，两层能力不能混写。
5. **正式界面与历史脚本**：主页面使用 `catalog.js` 等当前脚本；旧 `query.js`、`order.js` 和旧模板不能直接作为正式页面功能依据。
6. **建图原型**：`docs/design/mapping-preview.html`、`map_demo.html` 等是设计/演示资产；其中机器人位姿、地图原点等选项不代表已出现在正式对象下拉框。
7. **HTTP 实现**：当前启动的是 FastAPI/Uvicorn。标准库 HTTP 兼容处理代码保留，不代表项目仍以旧 `http.server` 作为主运行架构。
8. **三种包不混用**：页面 ZIP 是业务数据包；`.kpkg` 是旧式数据序列化/构建兼容能力；`.bin` 是应用源码和静态资源交付包。
9. **备份不等于全面容灾**：数据副本、配置备份、地图 STCM 备份、上一应用包各有范围；不构成统一数据库、全量灾备或跨版本自动恢复业务状态系统。
10. **业务能力边界**：项目不自建支付、采购、库存账本、配送结算、通用 AI 聊天或独立机械臂控制平台；依赖外部 Broker/设备执行的动作不应描述为项目内部完整实现。

本清单依据静态代码、正式页面和部署脚本交叉核对。仓库已有 Python/JavaScript 回归测试及文档截图工具，覆盖权限、数据加载、订单、日志、地图、文件/终端、代理和飞书等模块；这些是开发验证资产，不是额外业务页面。本次仅整理文档，未执行测试或进行设备联调。
